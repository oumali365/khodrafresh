## 📑 الترتيب الرسمي لوثائق الملف (مرتبة حسب أولوية العرض على اللجان)

### 1. [`01_Pitch_Deck.md`](./01_Pitch_Deck.md) — العرض التقديمي المختصر (Pitch Deck)
* **الغرض:** وثيقة العرض السريع (6 شرائح مركزة لمدة 3–5 دقائق) أمام لجان الانتقاء الأولي.
* **المحتوى:** المشكلة والحل، الجاهزية التقنية الكاملة للمنصة (MVP)، حجم السوق بفاس، اقتصاديات الوحدة، التوقعات المالية الموحدة، وتفصيل طلب التمويل (`100,000 درهم`).

### 2. [`02_Business_Plan_and_Operations.md`](./02_Business_Plan_and_Operations.md) — خطة العمل، الدراسة التقنية، والتشغيل الميداني
* **الغرض:** الوثيقة التقنية والتشغيلية الشاملة التي تثبت جاهزية التطبيق وقابلية التنفيذ الميداني في فاس.
* **المحتوى:**
  1. **الدراسة التقنية (Étude Technique):** البنية المعمارية (`React + TypeScript + PWA + Supabase + Cloudflare Turnstile + Leaflet GPS`) ولوحة الإدارة والمالية (`Mini-ERP`).
  2. **خطة التموين والتوصيل بفاس:** الدورة اليومية من سوق الجملة بنسودة، وتقسيم أحياء فاس إلى 4 قطاعات ذكية لتجميع المسارات (`Route Batching`).
  3. **مؤشرات الأداء القياسية (KPIs)** ومصفوفة **تقييم وإدارة المخاطر**.

### 3. [`03_Financial_Study_and_Budget.md`](./03_Financial_Study_and_Budget.md) — الدراسة المالية الموحدة وميزانية التجهيز
* **الغرض:** الملف المالي المتكامل بدون أي تضارب في الأرقام، جاهز للتقديم لخبراء المحاسبة ولجان التمويل.
* **المحتوى:**
  1. **البرنامج الاستثماري (Investment Budget):** مقارنة واضحة بين الانطلاق الذاتي الخفيف (`12,000 د.م`) والتمويل المؤسسي الكامل (`100,000 د.م`).
  2. **اقتصاديات الطلب الواحد (Unit Economics)** وحساب **نقطة التعادل (Break-Even)**.
  3. **جدول التدفقات والتوقعات الشهرية للسنة الأولى (12 شهراً)** والتوقعات الثلاثية (**3 سنوات**).

### 4. [`04_Legal_Contracts.md`](./04_Legal_Contracts.md) — الملاحق القانونية ونماذج العقود
* **الغرض:** إثبات النضج القانوني والتنظيمي للمشروع أمام المؤسسات المانحة والشركاء.
* **المحتوى:**
  1. عقد شراكة مع سائق توصيل (شامل شروط التحصيل النقدي `COD` وحفظ الطراوة).
  2. عقد توريد بالجملة `B2B` (للمطاعم، الفنادق، والمقاهي بمدينة فاس).
  3. عقد شراكة واستثمار.

## 🛠️ الوثائق التقنية والهندسية المستقلة (Technical Architecture & Engineering)

### 5. [`05_System_Architecture_and_Operation_Guide.md`](./05_System_Architecture_and_Operation_Guide.md) — الدليل التقني الشامل وهندسة المنصة وآليات الاشتغال
* **الغرض:** مرجع معماري مستقل تماماً لصاحب المتجر وفريق التطوير لفهم البنية البرمجية وآليات اشتغال المنصة بالتفصيل وتسهيل إضافة التحديثات والميزات المستقبلية بدون تشتيت (جاهز للطباعة عبر الرابط المستقل `/docs/system-architecture.html`).
* **المحتوى:**
  1. **الرؤية المعمارية والهندسة العامة:** نمط SPA + PWA الهجين ومرونة العمل في بيئة الاتصال المتقطع.
  2. **الترسانة والتقنيات البرمجية المتقدمة:** React 19، TypeScript 5.8، Supabase (PostgreSQL + RLS + Realtime)، Tailwind CSS v4، Swiper 14، Leaflet GPS، وCanvas Confetti.
  3. **خريطة الكود والمجلدات:** توثيق تفصيلي لكل مجلد ومكون داخل المشروع.
  4. **آليات الاشتغال ودورة حياة الطلب (Order State Machine):** من السلة وحتى التسليم والتحصيل.
  5. **محرك التقييمات وشارات الثقة:** منع التكرار بالمعرف والتنقل بدفعات منتظمة (4، 8، 12).
  6. **مخطط قاعدة البيانات وطبقات الأمان الست:** سياسات RLS، منع التكرار، وتنظيف المدخلات.
  7. **دليل التحديثات والتوسعة المستقبلية بدون تشتيت:** القواعد الذهبية وخارطة طريق الميزات القادمة (بوابات CMI، تتبع السائق، بوابة الموردين).

### 6. [`06_Comprehensive_Engineering_Audit_Report.md`](./06_Comprehensive_Engineering_Audit_Report.md) — تقرير التدقيق الهندسي الشامل وقرار الاستعداد للإطلاق
* **الغرض:** التقرير الهندسي والمحاسبي الموحد والنهائي لمطابقة الكود المصدري وقاعدة البيانات والنمذجة المالية مع القرار الفني الرسمي لجاهزية الإطلاق الإنتاجي.
* **المحتوى:**
  1. **ملخص نتائج الفحص الشامل وقرار الجاهزية:** اجتياز 41/41 فحصاً آلياً بنسبة 100%.
  2. **خريطة مسار البيانات وتدفق العمليات من البداية للنهاية:** من السلة وحتى الإغلاق المالي للجولة.
  3. **جدول مصدر الحقيقة المعتمد:** تصنيف مصادر الحقيقة بدقة (actual / estimated / unknown).
  4. **دليل المعادلات المالية والتشغيلية الموحدة:** معادلات التسعير بهامش 40% (Markup 66.67%)، التوصيل المجاني فوق 250 درهماً، الربح التشغيلي، وفصل المصاريف الثابتة (7,800 درهم).
  5. **تفكيك وتفسير الأرقام الثابتة:** (8، 15، 20، 25، 70، 250، 40%، 60%، 66.67%، 7800، 26 يوم، 30 دقيقة خمول).
  6. **تدقيق دورة حياة الطلب:** التراجع التلقائي (Rollback) عند فشل الاتصال، وصمام أمان تكلفة التوصيل.
  7. **تدقيق منظومة التوصيل والسائقين:** كباتن المتجر وتطبيقات التوصيل، وتوزيع كلفة الجولات المجمعة دون تكرار.
  8. **تدقيق أمان جلسة المدير:** مهلة خمول 30 دقيقة، تنبيه مبكر عند 28 دقيقة، وحظر استرجاع الجلسة عبر زر الرجوع.
  9. **مراجعة البنية التحتية وSupabase:** الجداول المركزية، دوال RPCs الذرية، وسياسات RLS.
  10. **جدول الأدلة والبراهين الفنية والتوصيات التشغيلية الميدانية (SOPs).**

### 7. [`07_Orders_and_Delivery_Integration_Audit.md`](./07_Orders_and_Delivery_Integration_Audit.md) — تقرير تدقيق وتحليل التكامل بين أداة الطلبات وأداة التوصيل
* **الغرض:** دراسة تحليلية مفصلة للعلاقة الحالية بين أداة الطلبات (`AdminOrdersPanel`) وأداة التوصيل والأسطول (`AdminDeliveryFleetTab`) في متجر «خُضرة».
* **المحتوى:**
  1. **العلاقة الحالية:** مصدر الحقيقة المشترك عبر Supabase والتكامل الجزئي عبر فرع التجهيز.
  2. **ميكانزمات العمل:** دورة حياة الطلب في فروع المراجعة، التجهيز، والتسليم والأرشيف؛ وتقسيم القطاعات الجغرافية الأربعة بفاس (`Zone Batching`) وتوليد مسارات Google Maps وبورديرو الشحن.
  3. **الفجوات والنواقص:** غياب التوزيع الجغرافي التلقائي للطلبات الواردة، انفصال جزئي في إسناد السائق، نقص التتبع المباشر لحظة بخطوة وتسوية النقدية اليدوية.
  4. **التوصيات والمقترحات التحسينية:** الأتمتة الذكية للطلبات الواردة، توحيد واجهة الإسناد، ومراقبة الخريطة الحية.
